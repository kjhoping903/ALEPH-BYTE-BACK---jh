# 방어회방어전 최종 커밋 새 환경 재현 기록

## 1. 재현 대상

이 기록은 2026-11-05에 원래 작업 폴더를 보존한 채 별도 폴더에서 수행한 학생 재현 기록이다. 서버가 새 환경에서 실행했다는 증명이나 운영 인증 결과가 아니다.

| 항목 | 기록값 |
|---|---|
| 저장소 URL | `https://github.com/kjhoping903/ALEPH-BYTE-BACK---jh.git` |
| 브랜치 | `stage14-submission` |
| 재현 기준 커밋 | `4d13fab52f54c5e9edb4ee8a9bcc99dae52ac93a` |
| 앱 패키지 버전 | `alekov-client-starter` 0.2.14 |
| 릴리스 상태 | 검증 중 |
| 최종 관찰 시각 | `2026-11-05T14:09:50+09:00` |

재현 결과 문서를 추가하면 다음 커밋의 SHA는 위 기준 SHA와 달라진다. 이 문서는 위 SHA에서 실제로 실행한 결과만 기록하며, 문서 추가 커밋을 실행 검증한 것처럼 표시하지 않는다. 코드 문제가 발견돼 수정되면 새 SHA를 받은 별도 빈 폴더에서 전 절차를 다시 수행해야 한다.

## 2. 원본 보존과 별도 복제 절차

원래 Git 최상위 폴더와 새 재현 폴더의 위치는 로컬 실행 증거이며 실행 명령이 의존하는 고정 경로가 아니다. 다른 PC에서는 원하는 빈 상위 폴더를 사용할 수 있다.

원본 확인 결과:

- 원본 HEAD: `4d13fab52f54c5e9edb4ee8a9bcc99dae52ac93a`
- 원본 작업 트리: 변경 없음
- 재현 후 원본 HEAD와 작업 트리를 다시 확인했으며 값이 유지됐다.

빈 상위 폴더에서 실행한 복제 절차는 다음과 같다.

```powershell
git clone --branch stage14-submission --single-branch https://github.com/kjhoping903/ALEPH-BYTE-BACK---jh.git ALEPH-BYTE-BACK---jh-stage22-repro
Set-Location .\ALEPH-BYTE-BACK---jh-stage22-repro
git checkout --detach 4d13fab52f54c5e9edb4ee8a9bcc99dae52ac93a
git rev-parse HEAD
git status --short
```

관찰 결과는 정확한 40자리 HEAD 일치, detached HEAD, 변경 파일 없음이었다. 원본 폴더의 `.env`, 사용자별 native 설정, SDP 설정, 인증서, 자격정보, 데이터베이스는 복사하지 않았다.

`package.json`에 외부 npm 의존성이 없고 lockfile도 없으므로 `npm install`은 실행하지 않았다. 설치하지 않은 상태에서 아래 문법 검사를 실행했다.

```powershell
Set-Location .\on-client
npm.cmd run check
node --check ..\student\extension.mjs
```

두 명령은 종료 코드 0이었다. 실행본과 루트 학생 파일의 blob은 서로 달랐으며, 21단계 문서에 기록한 대로 루트 복사본의 `renderEvents`와 `renderStatus`는 실행본과 구현 상태가 다르다. 이 누적 불일치는 22단계에서 수정하지 않았다.

## 4. 실행·종료·재실행

새 복제본의 `on-client` 폴더에서 21단계 설명서의 로컬 확인 명령을 사용했다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost
```

첫 실행과 재실행에서 모두 다음 정상 시작 신호를 관찰했다.

```text
케셰브 연결 확인: http://127.0.0.1:5189
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
```

첫 실행에서 `Ctrl+C`로 종료한 뒤 5189 포트가 닫힌 것을 확인했다. 같은 명령으로 재실행한 뒤 로컬 GET API를 확인하고 다시 `Ctrl+C`로 종료했다. 두 번째 종료 뒤에도 5189 포트가 닫혔다.

브라우저 확인은 다음처럼 구분한다.

- HTTP 확인: `http://127.0.0.1:5189/` 응답과 화면 원문은 확인했다.
- 일반 브라우저 UI: 자동화 도구가 현재 URL을 안전하게 판별하지 못해 중단됐으므로 실제 렌더링과 클릭은 미확인이다.
- Chrome 헤드리스 대체 확인: 기존 Chrome 프로세스와 분리된 DOM 출력을 얻지 못했으므로 성공 증거로 사용하지 않는다.

## 5. 같은 커밋의 로컬 API 관찰

재실행 중 외부 연동을 요구하지 않는 로컬 GET만 확인했다. POST, AI 요청, 조치 준비·실행은 호출하지 않았다.

| 주소 | HTTP | 관찰 상태 | 의미 |
|---|---:|---|---|
| `/api/me` | 503 | `ENGINE_NOT_CONNECTED` | 실제 계정 원천 연결 없음 |
| `/api/apps` | 503 | `ENGINE_NOT_CONNECTED` | 실제 업무 앱 원천 연결 없음 |
| `/api/events` | 503 | `ENGINE_NOT_CONNECTED` | 실제 접속·XDR 원천 연결 없음 |
| `/api/devices` | 503 | `ENGINE_NOT_CONNECTED` | 실제 기기 원천 연결 없음 |
| `/api/sessions` | 503 | `ENGINE_NOT_CONNECTED` | 실제 세션 원천 연결 없음 |
| `/api/diagnostics` | 200 | `ENGINE_NOT_CONNECTED` | 진단 API가 미연결 상태를 명시적으로 반환 |
| `/api/vulnerabilities` | 200 | `not_configured` | 프로젝트 경로·공개 패키지 허용 목록을 설정하지 않아 미조회 |

HTTP 200인 진단과 취약점 API도 외부 시스템 연결 성공이나 취약점 없음의 증거가 아니다.

## 7. 데이터 보존·백업·복원 계획

| 데이터 종류 | 현재 위치·소유 경계 | 보존·백업 계획 | 복원 계획과 제한 |
|---|---|---|---|
| 학생 소스·문서 | Git 추적 파일 | 변경 전 커밋하고 원격 SHA를 기록한다. 새 환경은 정확한 SHA를 별도 폴더에 clone한다. | 필요한 SHA를 새 폴더에 checkout한다. 미커밋 파일은 Git 복원 대상이 아니다. |
| `.env`와 인증·설정 파일 | Git 밖의 운영자 지정 위치 | 원문이나 비밀값을 Git·문서·재현 묶음에 넣지 않는다. 운영 승인 절차로 별도 백업한다. | 다른 경로에 무작정 복사하지 않고 운영자가 새 환경에 다시 발급·배치한다. 이번 재현에는 복원하지 않았다. |

백업·복원 계획은 절차 설명이며 이번 재현에서 비밀 설정, 외부 원천 데이터, 운영 DB의 백업이나 복원을 실행했다는 뜻이 아니다.

## 8. 증거 구분과 결론

| 증거 구분 | 이번 기록 |
|---|---|
| 원문 확인 | 기준 커밋의 코드·README·설정 견본·21단계 문서를 읽고 경계를 대조함 |
| 명령 실행 | clone, exact checkout, 버전 확인, 문법 검사, 첫 실행, 종료, 재실행, 로컬 GET, 최종 종료를 수행함 |
| 실제 화면 검증 | 일반 브라우저 렌더링·클릭은 미확인 |
| 모의 데이터 | 이번 재현에서 demo와 모의 fixture를 실행하지 않음 |
| 실제 시스템 연결 | 접근 제어·XDR·AI·OSV·보안 조치 모두 미확인 또는 미설정 |
| 서버 AI 검토 | 실행하지 않았고 통과를 주장하지 않음 |

현재 버전은 **검증 중**이다. 22단계 원문 검토를 통과하더라도 실제 운영 인증, 실제 19단계 집행 연결, v1.0 자동 인증을 뜻하지 않는다.
